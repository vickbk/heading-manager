# Security Policy

## Supported Versions

We actively release security updates and bug fixes for the current major version. Previous releases are supported on a case-by-case basis depending on severity.

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

We take the security of our application seriously. If you suspect you have found a security vulnerability, please **do not open a public GitHub issue or discuss it publicly.**

### How to Submit a Report

Please report vulnerabilities confidentially through one of the following channels:

- **GitHub Private Advisory (Preferred):** Go to the **Security** tab of this repository, select **Advisories**, and click **New draft security advisory**.
- **Direct Email:** Contact us at **`vickbake8@gmail.com`**.

### What to Include in Your Report

To help us triage and resolve the issue quickly, please include:

1. **Description:** A detailed explanation of the vulnerability and potential impact.
2. **Steps to Reproduce:** Clear, step-by-step instructions or a minimal Proof of Concept (PoC).
3. **Affected Components:** Specific endpoints, server actions, client components, or dependencies involved.
4. **Suggested Mitigation:** Optional, but appreciated if you have recommendations for remediation.

---

## Response Expectations & SLA

When you submit a report, here is what you can expect:

| Timeline                   | Milestone                                                                           |
| -------------------------- | ----------------------------------------------------------------------------------- |
| **Within 48 hours**        | **Initial Acknowledgment:** Confirmation that your report was received.             |
| **Within 5 business days** | **Triage & Assessment:** Initial findings on validity, severity rating, and impact. |
| **Within 14–30 days**      | **Patch & Resolution:** Deployment of fix and public disclosure coordination.       |

---

## Disclosure Policy & Safe Harbor

- **Coordinated Disclosure:** We ask that you give us reasonable time to investigate and fix the issue before publicly disclosing any details.
- **Safe Harbor:** Activities conducted in good faith, in alignment with this policy, and aimed at identifying vulnerabilities without harming users or disrupting services will be considered authorized. We will not pursue legal action against researchers acting in good faith.
